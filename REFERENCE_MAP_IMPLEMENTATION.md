# Reference Map Implementation Specification

The supplied visual reference is a desktop-first, dark discovery environment with one consistent browsing language. MyGF.ai will adopt its **structural system**—a compact navigation shell, prominent collection presentation, dense rounded-card browsing, a high-contrast conversion band, FAQ accordion, editorial trust content, and information-rich footer—while retaining original CSS-only art, MyGF.ai copy, and the existing pre-launch form flow.

| Reference-map behavior | MyGF.ai implementation |
| --- | --- |
| Compact product navigation and immediate discovery surface | A sticky MyGF.ai header with a visible “Worlds” collection entry and a private-beta CTA. |
| Dense four-column portrait catalog with metadata over a bottom gradient | A desktop-first companion-world gallery using original CSS gradient portraits, world tags, mood, first line, and clear beta CTA. |
| Occasional content-state badges | Original, non-deceptive labels such as “Private beta”, “New world”, and “Memory-ready design”; no fabricated live activity or user reviews. |
| Wide, bordered conversion band after the catalog | A private-beta band with clear adult-only/pre-launch language and the existing stored interest form. |
| Long, single-column FAQ | An original FAQ covering AI disclosure, memory control, privacy boundaries, beta access, and the form’s purpose. |
| Editorial explanation and dense footer | A concise MyGF.ai “built deliberately” section and a multi-column footer with product, trust, and beta navigation. |

The rebuilt page must preserve the exact approved trust labels, exact disclaimer, the required beta-interest fields and options, database persistence, owner notifications, native validation, accessibility affordances, and safe copy boundaries. It must not reproduce the reference’s branded assets, people, exact text, specific scenarios, or claims that blur the fact that the experience is AI.
