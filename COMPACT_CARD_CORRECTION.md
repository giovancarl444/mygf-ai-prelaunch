# Compact Companion Card Correction

## The Single Priority

The World Library must read as a **dense companion browser**, not an editorial sequence of individual profile dossiers. The supplied reference is the structural target for this surface: a stable multi-column grid of portrait-forward cards, compact category controls immediately above the results, and enough visible entries to encourage fast scanning.

## Card Contract

| Element | Corrected MyGF.ai treatment |
| --- | --- |
| Grid | Four equal columns on wide desktop; three columns on medium desktop; two columns on tablet; one column on narrow mobile. Cards do not become side-by-side feature layouts. |
| Portrait frame | A clean 3:4 image-only frame with no caption, label, gradient, hover effect, badge, or button over portrait pixels. |
| Dossier | A compact `76–92px` panel directly below the image. It contains only world type, adult age, name, and concise world title. |
| Removed from card face | Mood paragraph, opening-line quote, CTA, decorative orbit, and internal status label. These details belong in a future detail view, not a browse-grid tile. |
| Interaction | The entire card is keyboard-focusable and routes to the existing private-beta handoff. No button needs to consume card-space. |
| CSS-only previews | Use the same media geometry with abstract art and a small “CSS-only world preview” signal in the compact dossier—not inside the art frame. |

## Explicit Comparison

The current implementation’s failure was not the portrait media. It was the overly tall pink/orange/violet dossier blocks, which converted each result into a two-part showcase. The corrected version must retain the zero-overlay media boundary while matching the reference’s **one dominant portrait card plus a minimal adjacent metadata treatment**. The result should show at least one substantially denser row of worlds at an ordinary desktop viewport.

## Boundaries

The visual structure is being translated, not copied. MyGF.ai retains its own violet-neon identity, original world names, adult-only fictional AI disclosures, beta-access action, and product language. It will not reproduce reference branding, labels, text, characters, icons, promotional content, or text-over-image treatment.

## Visual Review Record

The corrected desktop card field now presents four uniform portrait-first tiles in one scan line, with an approximately `82px` metadata strip rather than the earlier large dossier panel. The mobile review confirms that tiles stack cleanly and retain the same image-only media followed by compact metadata geometry. CSS-only preview labels sit inside the metadata strip, never over the abstract art or a supplied portrait.

The supplied portrait media is loaded eagerly in the catalog to prevent blank cards during normal grid browsing. A final desktop capture confirmed all six supplied portraits and the CSS-only previews render in the same compact card system without metadata overlays on portrait pixels.
