# Sienna Vale Readiness Standard

**Purpose:** This standard is the required owner review before Sienna Vale can be described or presented as a live MyGF.ai companion. A saved provider character is a technical prerequisite, not a launch approval.

## Current Decision

> **Current status: hold from public companion positioning.** Sienna is technically connected to the provider but is not yet identity-aligned with the public Sienna Vale concept.

The verified provider record is a saved character mapped to durable ID `21555`. The recorded provider review describes a **28-year-old independent cultural editor** with a creative, reflective, witty direction. The current public page instead presents a **24-year-old bright, observant, lightly playful** Sienna with a separate supplied portrait. These are not the same approved character definition. The product must not imply that they are.

## Required Approval Criteria

| Review area | Launch requirement | Current state |
| --- | --- | --- |
| Provider lifecycle | Candidate has reached `saved` and has a durable provider `characterId`. [1] | Met for the existing technical mapping. |
| Identity brief | Name, adult age, biography, job/context, voice, and public positioning align to one approved Sienna specification. | Not met. |
| Visual truthfulness | Any portrait or generated media shown as Sienna is either the approved character media or clearly an editorial, non-provider representation. | Not met for a provider-character claim. |
| Conversation review | Owner reviews representative non-explicit text behavior for voice, boundaries, quality, and AI disclosure. | Not completed for an identity-aligned candidate. |
| Account experience | Explicit adult confirmation, selected room context, account ownership, local clear control, reporting, and rate limit operate as designed. | Technically implemented; not a product-launch sign-off. |
| Public copy | Landing-page language describes only approved availability and does not retain beta-interest or “coming soon” positioning. | Pending live-access transition. |

## Controlled Path to a Real Sienna

The owner first approves one final Sienna brief. A private provider candidate is then generated from that brief, polled until `ready`, reviewed, explicitly saved only if approved, and polled until `saved` returns its durable `characterId`. [1] The owner then maps only that exact saved identifier, updates public profile and media to match the approved character, reviews a representative private thread, and gives a final launch sign-off.

Generation, saving, and mapping are deliberate provider-side operations. They are not performed by this standard and require the owner’s explicit confirmation at the relevant review step.
